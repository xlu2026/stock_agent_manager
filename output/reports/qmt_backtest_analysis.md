## `order_target_percent` 版本结果（11:07）

用 QMT 自带 `order_target_percent` 替换手工下单后，结果反而变差：

| 指标 | 手工 `_equity`（11:03） | `order_target_percent`（11:07） |
|---|---|---|
| 单位净值 | **1.288** | 1.234 |
| 年化 | **4.8%** | 4.0% |
| 阿尔法 | 0.061 | 0.056 |
| 贝塔 | 0.577 | 0.613 |
| 夏普 | **0.116** | 0.085 |
| 胜率 | 55.7% | 56.3% |
| 平仓/开仓 | 287/335 | 270/320 |
| 累计差（vs 引擎） | **-4.06pp** | -8.06pp |
| 跟踪误差 | **4.22%** | 4.43% |

日志显示 `order_target_percent` 仍然报：

```
可用资金不足，不足以买入...
过滤零股后下单量 0 小于 1
```

原因：QMT 回测在同一 bar 内，卖出回款没有变成可用资金；
`order_target_percent` 按“持仓市值+现金”算目标，但下单时可用现金不足，买单被跳过。
这个 API 没有解决同 bar 现金结算问题，反而增加了跳单。

**结论：回退到手工 `_equity` 版本（sha `089dfd...`，NAV 1.288）更接近引擎。**
`order_target_percent` 版本不建议继续用。

## 结构性限制

QMT 回测无法在同一个 bar 内完成“卖出回款→再买入”：
- 手工 `order_shares` 和 `order_target_percent` 都出现资金不足；
- 要完全消除，只能做两阶段调仓（月末卖、下一交易日买），
  但引擎是“t-1 信号、t 日收盘调仓”，两阶段会引入一天时滞，必须同步改引擎。

所以当前 `-4.06pp / TE 4.22%` 的更像是：
- QMT 同 bar 现金约束导致的低配；
- 100 股整手；
- 数据/成交价细节。
