杂灵根散修录 · AI技术 001

昨天的开篇由 agent 推进草稿箱。今天把这条管道拆开，记录它卡住的四个地方，以及发布为什么留在人工环节。
## 分工

本文由我口述、AI 协助整理，观点与判断由我负责。

我一个人写稿，时间有限。每篇都从打开编辑器开始，成本太高，所以排版、封面、换行、错别字和推送交给 agent；写什么、删哪句，仍由我决定。

这件事我按三层看：能力层，接口、报错、权限的处理；证据层，策略与市场认知留存为可复查的记录；内容层，过程本身成为素材。三层各自成立，这件事就值得继续。

第一步：取 AppID 与 AppSecret

入口已不在公众号后台。登录后台，设置与开发 →「开发接口管理」，页面会提示开发管理模块已迁移，点链接跳转到微信开发者平台。

进入平台后向下滚动，「我的业务」中选择公众号，进入「基础信息」。AppID 在页面顶部；继续向下，「开发密钥」中有 AppSecret 与 IP 白名单。AppSecret 首次需要启用，忘记则只能重置，平台不保存它。

有两个容易踩的地方。一个号只有一个 AppSecret，重置后旧值立即失效，在用的脚本会一并中断；重置前先确定新值写入哪里，重置后先取一次 token 确认。另一个是白名单需要填写调用方的出口 IP，宽带重播后可能变化。

token 有效期 7200 秒。每次运行用 AppSecret 换取一张，脚本不保存；过期的是换来的那一张，下一次运行重新换取。注意不要重复换取：连续换取两次，前一张会失效，接口返回 40001。当前脚本仍是每次现取，缓存尚未实现。

第二步：准备封面素材

草稿必须有封面。先把图片上传到素材库，取得永久素材 ID，再带着这个 ID 创建草稿。

封面按 2.35:1 输出；列表卡片还会再裁一次，主体放在中间。

第三步：写入草稿

正文按 HTML 提交，接口不接受 Markdown；编辑器会破坏代码块格式，所以步骤图用截图，代码保留在仓库里。

写入完成后得到的是草稿，尚未发布。发布需要在后台手动完成。

卡住的四个地方

40164：IP 不在白名单。errmsg 中会回显调用方 IP，加入白名单即可。这属于配置问题，与接口权限无关。

40007：invalid media_id。用占位 ID 试探时被拒绝；被拒绝说明权限可用，缺少的是素材。

HTTP 200 不表示成功。微信的错误信息在响应体里，第一版脚本只判断状态码，把失败读成了可用。

整篇覆盖。更新一次正文，后台手选的原创、赞赏、AI 声明和广告设置会一并清除。顺序固定为：改稿、推草稿、手选、发布；反过来操作，之前的手选会被清掉。

发布留在人工

发布接口没有接入，原因有两个。

一是责任归属：号在本人名下，发布内容由我承担。

二是这些设置不在接口字段里：原创声明、赞赏、AI 声明都没有对应字段，只能在编辑器里勾选。

自动化到草稿为止，发布保持在人工环节。

下一步

这期没有新的回测数字，回测链路仍只跑在合成样本上：前期回测基于合成数据，仅用于验证研究链路，不代表真实市场表现，不构成任何策略有效性证据。

下一期准备把「回测完成」到「草稿待写」之间的派活规则写进代码，由代码判断，减少每次手动决定。

再往后计划写四类内容：失败的实验、被市场纠正过的判断、关键节点上的选择，以及技术分享。开篇的三条规矩继续适用：记录过程，不展示输出，不给方向。

管道的作用是减少重复操作；省下的时间用于复盘判断错误。
