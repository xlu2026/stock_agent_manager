杂灵根散修录 · AI技术 002

agent 能生成订单提案，却不能自己提交。三段式、哈希绑定、一次性提案与过期时间，四道闸门各自拦住一种错。

三段

第一步，broker_propose_order 生成提案文件，不产生订单。

第二步，人在终端里跑 python -m quant.broker.approve <提案ID>，写入批准记录，记录里含提案内容的 sha256。

第三步，broker_submit_order 校验批准记录、哈希、有效期、是否已提交，全部通过才成交。

提案里有什么

提案包含标的、方向、数量、参考价、来源实验 ID 和生成时间。它是一份待批文件，本身不产生任何委托。

批准记录绑定这份内容的 sha256。批准之后改数量、改标的、改价格，哈希都会变，批准随之作废。

四道闸门

人工确认：OrderRequest.human_confirmed 为假一律拒单（NOT_CONFIRMED），模型不能自己填 true。

哈希绑定：批准记录绑定提案内容的 sha256，改动即失效。

一次性：提交过就打标记，重复提交返回 ALREADY_SUBMITTED。

有效期：提案默认 30 分钟过期。

为什么 approve 不进 MCP

把批准包成 MCP 工具，agent 就能自己调，人只剩旁观。量化 profile 没有 shell，approve 只能在终端里跑——这个设计把「人必须动手」变成结构约束。

为什么是 30 分钟

有效期是工程取舍：太短，人还没来得及看完就过期；太长，价格已经变了，批准却在等提交。三十分钟够核对一份提案，也不至于让旧价格一直有效。

风控与审计

PaperBroker 里还有三样：RiskLimits 管单笔名义金额、单日单数、单标的持仓上限与现金充足性；每笔（含被拒的）追加一行 JSONL 台账，记录时间、标的、方向、数量、价格、费用、实验 ID 和确认标记；同一 client_order_id 重复提交直接拒。

限价单不猜价：参考价取市场价，限价只判断是否触价，未触价就是 PENDING，不动资金。

为什么值得多做一步

提案写错，成本是一行日志；提交写错，成本是真金白银。两端的代价差得很远，中间加一道人，是为这个不对称付的费。

人也会出错。批准这一步的价值在于：一个决定至少经过两次独立判断，第二次留下了签名和时间。

现状

只有 PaperBroker，没有任何真实券商适配器。下单能力只存在于量化 profile，写作侧没有。

这条线的作用

让错误在变贵之前被拦住。提案便宜，批准便宜，提交出去才贵。

闸门与台账实现见 quant/broker/；当前只有 PaperBroker，接真实通道前还需要先跑稳模拟盘。
