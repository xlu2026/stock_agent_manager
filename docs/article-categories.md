# 文章分类（栏目）

四类，front matter 的 `category` 只写这四个值之一。对应公众号后台的"合集"，发文时勾同一个。

| 值 | 收什么 | 边界 |
|---|---|---|
| `量化研究` | 因子构造、回测、数据口径、实验记录、策略开发日志 | 不写标的、不写买卖点；数字只能来自 `quant/engine.py` |
| `AI技术` | agent 与工具链、工作流、接口排障、开发日志 | 不写"AI 能稳定赚钱"这类暗示 |
| `市场复盘` | 复盘、被市场纠正过的判断、风险记录 | 只记过程与教训，不展示持仓、不给方向 |
| `杂项` | 发刊词、账号运营、写作流程，以及前三类装不下的东西 | 兜底用，不是垃圾桶；成系列了再议是否单立 |

## 怎么判

一篇文章只归一类。跨界的按"读者为什么点开它"判：

- 看"这套方法怎么跑" → 量化研究
- 看"工具怎么用、流程怎么搭" → AI技术
- 看"这次判断错在哪" → 市场复盘
- 都不是 → 杂项

杂项是兜底而不是垃圾桶：同一主题在杂项里写到第三篇，就该考虑升成正式栏目，而不是继续堆着。
反过来，拿不准时宁可先放杂项，也别硬塞进 AI技术——分类错了比没分类更难找。

## 副标题与编号

格式固定一行，放在标题下、正文前，斜体：

```
*系列名 · 栏目 编号*
```

例：`*杂灵根散修录 · AI技术 001*`

- **栏目名直接写 `category` 的值**：量化研究 / AI技术 / 市场复盘 / 杂项。副标题和 front matter 必须一致，
  改栏目时两处一起改。
- **编号按栏目各自计数，从 001 起**：AI技术 001、AI技术 002……与量化研究的 001 互不相干。
  每个栏目自成一条线，读者看到「AI技术 002」就知道是本栏目第二篇。
- **编号不回收**。某栏目里归档的号保留，新文章往后排；改号会让已经发出去的引用失效。
- **刊头不占隐喻配额**。标题和副标题里的"苟住/灵根/散修"是账号名，不是修辞；
  `writing/compliance.py` 的文风自检会先剥掉 H1 和副标题再数段落。

重新生成：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\make_category_covers.ps1
```

脚本用 GDI+ 写中文，改标题/标语只改脚本里的 `$Cats`。注意 `.ps1` 必须存成 **UTF-8 with BOM**，
否则 Windows PowerShell 5.1 会按 ANSI 读，中文变乱码。

## 落地方式

- 代码侧：`writing/article.py::CATEGORIES` 是唯一取值表；未指定或认不出的值一律落 `DEFAULT_CATEGORY`（`杂项`），
  不会把 `认知记录` 这类旧值原样漏进 front matter。
- 简报侧：`examples/brief_demo.json` 用 `category` 字段指定，重渲染不会丢。
- 已发布稿改分类只动本地 front matter，不影响线上文章；真正要改的是公众号后台的合集归属。
