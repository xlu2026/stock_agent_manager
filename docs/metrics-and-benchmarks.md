# 指标与基准口径（2026-11-28）

> 目的：避免把不同基准、不同成本、不同风险口径的数字放在一张表里比较。
> 任何“跑赢/超额/alpha”必须同时注明：数据版本、区间、基准、成本、权重方式。

## 1. 研究基准（唯一主基准）

**40 只 PIT 等权、每日再平衡、零成本。**

实现：`quant/engine.py` 的 `benchmark_nav`：

- 每个交易日取 `panel.allowed_at(i)` 的有效池；
- 当日等权持有；
- 每日再平衡；
- 不计成本。

报告中统一叫 **“PIT 等权基准”**。

### 为什么不直接用沪深300

- QMT 的基准字段只能选 `000300`；
- 当前快照没有指数序列，引擎算不了 HS300；
- 两个基准的行业/市值分布不同，直接比“超额”会混入基准差异。

HS300 只能作为**展示性参考**，不能和研究结论的“超额”混用。

## 2. 指标定义

| 指标 | 口径 |
|---|---|
| `total_return` | 区间末净值 / 区间初净值 - 1 |
| `cagr` | `(1+total_return)^(252/交易日数)-1` |
| `sharpe` | 日收益均值 / 日收益标准差 × √252，**rf=0** |
| `max_drawdown` | 净值峰谷最大回撤 |
| `annual_volatility` | 日收益标准差 × √252 |
| `excess_cagr` | 策略 CAGR - **PIT 等权基准** CAGR |
| `annual_turnover` | 年化单边换手（引擎口径） |
| `monthly_win_rate` | 月度正收益占比 |

### 不使用的指标

- **QMT 的阿尔法**：基准是 000300，且风险模型口径不同，不能和研究结论并列；
- **QMT 的基准年化**：只做界面展示；
- **未注明 rf 的夏普**：必须写 `rf=0`，否则不可比。

## 3. 成本口径

| 场景 | 口径 |
|---|---|
| 引擎研究 | `cost_bps` 单边全包，默认 10bp；按换手扣 |
| 成本敏感性 | 10/20/30/50bp 各跑一次，报告净超额 |
| QMT 回测 | 买入/卖出/平昨/平今各 0.1%，印花税 0，滑点 0 |
| QMT paper | 以实际成交佣金/费用为准 |

研究结论必须说明成本档；10bp 下的正超额不能直接推到 30bp。

## 4. 可比性检查清单

两张表放一起前，逐项确认：

- [ ] 同一 `data_version`
- [ ] 同一 `start/end`
- [ ] 同一 `universe`
- [ ] 同一 `strategy/params`
- [ ] 同一 `top_k`/`weighting`
- [ ] 同一 `cost_bps`
- [ ] 同一基准（PIT 等权）
- [ ] 同一 Sharpe rf 口径

任何一项不同，只能叫“对照”，不能叫“复现”。

## 5. QMT 对账口径

- QMT 策略 NAV 只和**同一份 QMT 数据**上的引擎实验比；
- 不和 baostock 影子直接比 NAV 绝对值；
- QMT 的 000300 基准/alpha 不进入研究结论；
- 跟踪误差、相关性、累计差可以报，但要注明“执行近似”。

## 6. 一句话

> 研究结论只认：同一数据版本、同一区间、同一 PIT 等权基准、rf=0、注明成本档的引擎结果。
> QMT 只回答“执行像不像”，不回答“策略有没有效”。
