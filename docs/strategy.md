# 策略规格（Strategy Spec）

这份文档记录**策略是什么**，不记录"怎么实现"（实现看代码）。它的作用有三个：

1. 让改策略的人先看懂现有口径，别凭印象改；
2. 让文档里的数字能指回 `experiments/` 里的记录；
3. 让"改了什么"有地方留痕——**版本号不是装饰，是复盘时的坐标**。

> 文档版本：**v1.0**（2026-11-08）
> 代码锚点：`ENGINE_VERSION = engine-0.1.0`、`spec_version = 1.0`、数据 `dv-572bafec2a92`

---

## 0. 版本规则

### 0.1 什么时候升版本

| 变更 | 版本动作 | 例子 |
|---|---|---|
| 改范式（选股逻辑、组合构建方式） | **主版本 +1**（v1 → v2） | 单因子等权 → 多因子加权 |
| 加/删因子、改权重方案、改成本口径 | **次版本 +1**（v1.0 → v1.1） | 加一个换手率因子 |
| 改参数默认值、改文档措辞 | 次版本 +1，但在变更记录里注明"仅默认值" | top_k 默认 10 → 12 |
| 只修错别字 | 不升版本 | —— |

判断标准只有一条：**读这份文档的人，会不会因为这个改动而做出不同的决策**。会，就升版本。

### 0.2 废弃的策略不删

旧版本条目保留，状态改成 `deprecated`，并写明"为什么废弃"。删掉等于销毁证据——
半年后你只会记得"当时那个策略不行"，但想不起来具体哪里不行。

### 0.3 文档版本 ≠ 实验 ID

文档版本描述"口径"，实验 ID 由 `spec + 数据快照` 的指纹算出。同一版策略可以有很多实验。
所以每条实测数字都必须带 `experiment_id`，否则不可追溯。

## 2. S1 · 单因子截面等权（v1.0）

### 2.1 一句话

在标的池内按单个因子的值做横截面排序，取前 `top_k` 只等权持有，按固定频率调仓，只做多、不加杠杆、不对冲。

### 2.2 参数与默认值

| 参数 | 默认 | 取值 | 含义 |
|---|---|---|---|
| `factor` | 必填 | 见 2.3 | 用哪个因子排序 |
| `universe` | 必填 | `synthetic_40` / `沪深300` / 快照内池名 | 标的池；`沪深300` 映射到 `hs300_40_pit` |
| `start` / `end` | 必填 | `YYYY-MM-DD` | 回测区间（含端点） |
| `rebalance` | `M` | `M` / `W` / `Q` | 月末 / 周末 / 季末调仓 |
| `top_k` | `10` | 1–40 | 持仓只数 |
| `weighting` | `equal` | `equal` | 权重方案（目前只有等权） |
| `cost_bps` | `10` | ≥0 | 单边换手成本（万分之一为单位） |
| `seed` | `42` | ≥0 | 保留字段；当前引擎无随机数 |
| `data_version` | 空 | `dv-…` | 固定数据快照；不填则用当前快照 |

### 2.3 因子定义

四个因子都在 `quant/factors.py`，接口统一为 `fn(panel, asset, i)`，**只能读下标 ≤ i 的数据**。

| 因子 | 定义 | 预热 | 实现 |
|---|---|---|---|
| `momentum_12_1` | `close[i-21] / close[i-252] - 1`，即 12 个月动量剔除最近 1 个月 | 252 | `factors.py:28` |
| `value_proxy` | `book[i] / close[i]`，账面价值 / 股价，越高越"便宜" | 1 | `factors.py:39` |
| `low_vol_60d` | 过去 60 个交易日日收益标准差的负值 | 60 | `factors.py:47` |
| `quality_proxy` | `earnings[i] / book[i]`，TTM 盈利 / 账面价值（ROE 代理） | 1 | `factors.py:59` |

预热天数登记在 `factors.MIN_HISTORY`，`validate.py` 会据此检查 `start` 之前的历史是否足够。
加因子时这三处（函数表 / 预热表 / `spec.FACTORS`）必须同时登记，否则 import 时直接报错。

### 2.4 组合构建与执行

```
调仓日 t：
  1. 用 t-1 日收盘数据计算因子值（信号）
  2. 截面降序排序，取前 top_k（同分按代码升序，保证确定性）
  3. 等权买入，权重 1/top_k
  4. 换手 = 0.5 × Σ|w_new − w_old|
  5. 成本 = 换手 × cost_bps / 10000，从当日净值直接扣
```

关键约定：

- **信号只用 t-1 及以前**，`signal_date = fill_date − 1 个交易日`，有单测守着；
- **建仓日只计成本、不计当日收益**（保守处理，不会高估）；
- **不设止损、不择时、不留现金**，除非当日无合格标的；
- **基准**：全池等权、日频再平衡、零成本。

### 2.5 指标口径

| 指标 | 算法 |
|---|---|
| `cagr` | `nav[-1] ** (1/年数) − 1`，年数按自然日 / 365.25 |
| `annual_volatility` | 日收益标准差 × √252 |
| `sharpe` | 日均收益 / 日标准差 × √252（无风险利率取 0） |
| `max_drawdown` | 净值相对历史峰值的最大跌幅（负数） |
| `calmar` | `cagr / |max_drawdown|` |
| `monthly_win_rate` | 月度收益 > 0 的月份占比 |
| `annual_turnover` | 累计单边换手 / 年数 |
| `nav_hash` | 全净值序列的 sha256，用于复现校验 |

IC 口径（`run_factor_analysis`）：调仓日因子值与到下一调仓日的收益做 Spearman 秩相关，
报 `ic_mean`、`ic_std`、`ic_ir`、`ic_t_stat`、分位收益与单调性。

### 2.6 实测结果（合成样本，非真实行情）
**规格**：2020-01-02 → 2024-12-31，月度调仓，`top_k=8`，`cost_bps=10`，数据 `dv-572bafec2a92`。
**基准 CAGR**：4.08%

| 因子 | CAGR | Sharpe | 最大回撤 | 年换手 | 月胜率 | IC 均值 | ICIR | 分位单调 | 实验 ID |
|---|---|---|---|---|---|---|---|---|---|
| `momentum_12_1` | 11.15% | 1.42 | −14.3% | 2.20 | 56.7% | 0.0506 | 0.32 | ✅ | `exp-a359c2d77697` |
| `value_proxy` | 20.87% | 2.48 | −16.4% | 1.70 | 65.0% | 0.0708 | 0.44 | ❌ | `exp-a47bf0485ed2` |
| `low_vol_60d` | **−6.94%** | −0.91 | **−48.6%** | 6.10 | 40.0% | **−0.0646** | −0.45 | ❌ | `exp-2ac505ca8d3f` |
| `quality_proxy` | 8.77% | 1.12 | −26.3% | 4.33 | 58.3% | 0.0307 | 0.19 | ❌ | `exp-4aa1a34ba68b` |

**怎么读这张表**：

- 数字只能说明"流水线有没有接错"，**不能**说明"策略能不能赚钱"——数据是合成的；
- `low_vol_60d` 方向为负、换手最高，是这份数据里最明确的"不成立"；
- `value_proxy` 收益最高但分位不单调，正 IC 可能集中在少数档，样本外最脆弱；
- 四者中只有 `momentum_12_1` 的分位收益严格单调。

> 上述数字全部来自合成快照 `dv-572bafec2a92`，只用于验证链路。真实 baostock 快照
> （`dv-946b080b1258`，40 只时点成分）的同参数对照不混进本表，见
> `output/reports/real_vs_synthetic.md`；两者方向不一致时，以真实快照的结论为准，
> 但仍不构成策略有效性证据。

### 2.7 已知偏差与失效条件

| 偏差 | 现状 | 影响 |
|---|---|---|
| 合成数据 | 默认池是 `synthetic_40`；真实数据需 `--latest` / `NFR_DATA_DIR` 显式切换 | 合成数据结论不可外推；真实数据也有 baostock 单源与重述风险 |
| 无流动性约束 | 按收盘价无限量成交 | 小市值/低流动性标的上会严重高估 |
| 无涨跌停、无停牌 | 合成数据不存在 | 真实数据下部分信号根本无法成交 |
| 固定成本 | 单一 `cost_bps`，无滑点与冲击 | 高换手策略（如 low_vol 的 6.1 倍）被低估成本 |
| 无风险模型 | 不做行业/规模中性 | 因子收益可能只是行业或市值的暴露 |
| 等权满仓 | 无仓位管理、无止损 | 回撤完全由因子本身承担 |

## 3. 修改或新增策略的流程

### 3.1 先判断属于哪一类

| 类型 | 动什么 | 是否升文档版本 |
|---|---|---|
| 调参数 | 只写 spec | 否（除非改默认值） |
| 加/删因子 | `factors.py` + `spec.py` + `instruction.py` | 次版本 +1 |
| 改组合构建 | `engine.py` + `spec.py` | 次版本 +1 |
| 新范式 | 新增 `quant/portfolio/` 层 | 主版本 +1，新策略 ID |

### 3.2 加因子的 checklist

- [ ] `quant/factors.py`：写函数，签名为 `fn(panel, asset, i)`，只读 `≤ i` 的数据
- [ ] 同文件 `FACTOR_FUNCS` 注册
- [ ] 同文件 `MIN_HISTORY` 登记预热天数
- [ ] `quant/spec.py::FACTORS` 加一行（工具 schema 的 enum 靠它）
- [ ] `quant/instruction.py::FACTOR_KEYWORDS` 加关键词（**唯一不会自动报错的一处**）
- [ ] 补单测：同输入同输出 + 信号日严格早于成交日
- [ ] 同参数对照回测：与现有因子比 IC，并算相关性（>0.9 说明只是换名字）
- [ ] 更新本文档 2.3 与 2.6

### 3.3 改组合构建的 checklist

- [ ] 新参数加进 `Spec` 的 `OPTIONAL`，**并加进 `Spec.canonical()`**
      （漏了会让两个不同的策略算出同一个 `experiment_id`，实验档案悄悄串号）
- [ ] `WEIGHTING` 枚举扩容
- [ ] `engine.py` 里替换写死的等权分支
- [ ] 补单测：两种权重方案必须得到不同的 `nav_hash`

### 3.4 跑完必须做的三件事

1. `python -m unittest discover -s tests -t .`
2. `python scripts\acceptance.py`
3. 把新实验的 `experiment_id` 写进本文档 2.6 或新策略条目

## 4. 不能破的五条不变量

1. **因子只读 ≤ i**：任何全期统计（全样本均值、标准化）都会引入前视偏差；
2. **无随机、无时钟**：不能出现 `random`、`datetime.now()`，也不能依赖 `set`/`dict` 的迭代顺序；
3. **新参数进 `canonical()`**：否则实验 ID 碰撞；
4. **比较必须在同一 `data_version` 下**：数据一变，旧结论全部作废；
5. **失败实验也要留档**：`experiments/` 是公开日志，否定结果比成功结果值钱。

## 5. 一个文件放几个策略

**可以放多个，但有边界：**

| 情况 | 做法 |
|---|---|
| 1–3 个策略，总长 < 500 行 | 单个 `strategy.md`，用 `## 2. S1`、`## 3. S2` 分节 |
| 超过 3 个，或单文件超 500 行 | 拆成 `docs/strategies/S1-*.md`，本文件只留索引与通用规则 |
| 策略之间有继承关系 | 子策略单独成文，在父策略里链接，不要复制粘贴共用部分 |

拆分的触发条件写成"策略数或行数"，是为了避免拍脑袋：现在 1 个策略、约 200 行，不该拆；
到第 4 个策略时再拆，索引页天然变成导航。
